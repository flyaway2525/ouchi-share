# ouchi-share 設計メモ

## 画面とポップアップの閉じ方（決まり）

- 画面が切り替わる操作（メニューから別の画面へ）は、ポップアップを閉じてそのまま移る
- 画面が切り替わらず、ポップアップが重なっていくもの（メニュー → 下の段 → 確認、など）は、
  「‹ 戻る」「キャンセル」「閉じる」（null / false で閉じる）でひとつ前のポップアップに戻る（ui.js の openSheet の「重なり」）
  - ボタンで閉じて 1.5 秒以内に次のポップアップが開いたら、閉じたものを「ひとつ前」として覚える。項目を選んだ（undefined）ときも同じ
  - 保存・決定など値で閉じたら戻らない。背景のタップ・下スワイプは全部閉じる。画面が切り替わったら忘れる
  - ひとつ前があるとき、メニュー（actionSheet）のいちばん下のボタンは「‹ 戻る」
- テキスト予定表（画面）：「✕ 閉じる」（書き換えがあれば破棄してよいか確かめて前の画面へ。左上の ‹ も同じ）／
  「↺ 元に戻す」（今のカレンダーの内容に戻す）／「💾 更新」（反映してこの画面に残る）

## バージョン

- ホームのタイトルの横に「v75」のように出す（js/version.js の APP_VERSION）。タップで「このアプリ」と「公開中の最新」（version.json）を比べる
- 公開中の最新のほうが新しいときは「v74 更新あり」（赤）。Web 版は「再読み込みして最新にする」、iPhone アプリ版は TestFlight の更新待ち
- プッシュする前に毎回 `node scripts/bump-version.mjs "変更の内容"`：js/version.js・version.json・sw.js のキャッシュ名・CHANGELOG.md をまとめて 1 つ上げる

家族・友だちの小さなグループで「予定」「やること・欲しいもの」「思い出」を一か所で共有するのが目的。詳しくは各節。

| 📅 カレンダー・普段の予定 | 歯医者・習い事など日々の予定を全員で見る。人で絞り込める | カレンダーと普段の予定 |

| ✈️ イベント・旅程 | 旅行など期間のある予定と、その日ごとの行程・持ち物リスト | イベントと日常・旅程 |

| 欲しいもの系リスト | 欲しいもの・行きたいところ・食べたいものを、リンクの写真付きでためる。❤️ で欲しい度 | 欲しいもの系リスト |
| 貸し借りリスト | 立て替えたお金・貸したものを、一人ずつの差し引きで見る | 貸し借りリスト |

| 📢 お知らせ | アプリからのお知らせ・グループのお知らせ（管理者お知らせ）を、未読ならポップアップ | お知らせ |

## 方針

- アプリの形は 3 つ（ブラウザ版・ホーム画面版・アプリ版）。どの端末・形でどう動かすかは CLAUDE.md の「対応する環境」
- 画面は静的サイトとして GitHub Pages で公開（ビルド不要の素の JavaScript）。アプリ版は同じファイルを Capacitor で包む
- データは Firebase（Firestore + Authentication）でメンバー間リアルタイム同期
  - Spark（無料）プランで運用。無料枠を超えても課金はされず、その日は止まるだけ
  - 端末にもキャッシュするので、オフラインでも表示・編集でき、つながったら同期される
- 通知とリンクのタイトル・画像の取得は Cloudflare Workers（無料プラン）。費用は Apple Developer Program の年 99 ドルだけ

## データ構造

```
admins/{uid}                        グループを作れる人の許可リスト（コンソールから手で追加）
config/{docId}                      アプリ全体の設定（ログボの配布表など。アプリの管理者が書く）
announcements/{id}                  アプリからのお知らせ
reads/{uid}                         お知らせの既読
push/{uid}                          通知の送り先（端末のトークン）と受け取る種類
profiles/{uid}                      全体のプロフィール { icon, photo, title, colors }
presence/{uid}                      最終アクセス時刻 { lastSeen, name, guest }（本人と管理者だけ読める）
recovery/{code}                     ゲストの復旧ID { groupId, uid, name, createdAt }
groups/{groupId}
  ├─ name, createdAt, createdBy
  ├─ inviteCode                     招待リンクに含める合言葉。作り直すと古いリンクは無効
  ├─ memberIds: [uid, ...]          「自分が入っているグループ」を検索するための配列
  ├─ members: { uid: { name, role, guest, joinedAt, lastSeen, icon, photo, title, colors, custom } }
  │                                  role = owner / admin / member。icon〜custom はグループでのプロフィール
  ├─ events/{eventId}               イベント（旅行など）{ title, emoji, startDate, endDate, participants }（日付は "YYYY-MM-DD"）
  ├─ plans/{planId}                 普段の予定（歯医者など）{ title, date, endDate, start, duration, place, memo, links, participants }
  ├─ lists/{listId}
  │     ├─ eventId                  イベントのリストならそのイベント ID、日常のリストなら null / なし
  │     ├─ type: checklist | schedule | money | wish（variant: buy / place / food）| inventory（予約。まだ使っていない）
  │     ├─ title, emoji, order, createdAt, createdBy
  │     └─ items: { itemId: {...} } 種類ごとの中身。通常のリストは { text, checked, order, links, createdAt }
  ├─ photos/{photoId}               写真（縮小した JPEG の data URL。Storage は無料プランで使えないため）
  ├─ announcements/{id}             グループのお知らせ（official = 管理者お知らせ）
  ├─ bonus/{uid}                    ログインボーナスの記録（連続日数・スタンプ・チケット）
  ├─ rewards/{id} / redemptions/{id} / settings/{docId}   ごほうび・交換の記録・チケットのレート
  ├─ diary/{id}                     日記 { title, at, members, tags, body, createdAt, createdBy, updatedAt }
  └─ diaryTags/{id}                 日記のタグ { name }
```

- アイテムはリストのドキュメント内のマップに入れている
  - 1 リスト = 1 ドキュメントなので読み取り回数が少なく、無料枠にやさしい
  - アイテムごとにフィールド単位で更新するので、同時に別のアイテムを編集しても上書きし合わない
  - 1 ドキュメント 1MB までなので、数千件規模のリストには向かない（家庭用途なら十分）

## オンライン表示

- アプリが画面に表示されている間、1 分ごとに `presence/{uid}.lastSeen` を記録する
  - グループ（またはその中のリスト）を開いているときは `groups/{id}.members.{uid}.lastSeen` にも記録する
- `lastSeen` が 2.5 分以内ならオンラインとみなす（閉じてから消えるまで最大 2〜3 分の遅れがある）
- グループ画面：そのグループを見ているメンバーを 🟢 で表示
- 管理者ダッシュボード（`#/admin`）：全体のオンライン数・24 時間以内・累計（ゲスト / Google 別）
- 書き込みは 1 人 1 分に 1〜2 回。家族規模なら無料枠（1 日 2 万回）に十分収まる

## イベントと日常

- グループの画面は「📅 カレンダー」「✈️ イベント」「📝 リスト」（日常のリスト）「📔 日記」のタブ。イベント（期間のある予定）の中にも、そのイベントのリストがある
- イベントはこれから・開催中を日付の近い順に表示し、終わったものは「過去のイベント」に折りたたむ
- リストは 1 つのコレクションにまとめ、`eventId` で所属を表す（取り込みのコピーが簡単）
- 取り込み
  - A. リストを丸ごと新しいリストとしてコピー（「＋ リストを追加」→「ほかのリストを丸ごと取り込む」）
  - B. 今のリストに選んだアイテムを追加（リスト画面の ⋯ →「ほかのリストからアイテムを追加」。同じ名前のものは最初から外しておく）
  - どちらもチェックは外した状態で入り、元のリストとは別物になる
- イベントを消すと、中のリスト（旅程を含む）も消える
- 並べ替え：リストのカードと、チェックリストの未チェックのアイテムは、長押しで持ち上げて上下に動かせる（enableLongPressSort）。
  リストは `order`、アイテムは `items.{id}.order` に 0, 1, 2… を書く。order のないもの（新しく足したもの）は作った順で一番下。
  長押しの前に指が動いたらスクロール。持ち上げている間は画面の描き直しを待ち、離したあとのタップは無視する
- リストのカード（グループ・イベントのリストタブ）は、1 回目のタップでその場に中身を開き、もう一度で閉じる。開けるのは 1 枚だけ（開くとほかは閉じる）。「開く ›」でリストの画面へ
  - やることリスト：未完了 → 完了の順に 8 件まで。その場でチェックできる
  - 貸し借り：一人ずつの差し引きと、未精算の貸したもの ／ 欲しいもの：未完了のもの
  - 開いているカードは描き直しても保つ（アプリを開き直すと閉じる）

## 旅程（イベントのスケジュール）

- イベントごとに `type: 'schedule'` のリストを ID `sch-{eventId}` で 1 つ持つ（最初の予定を追加したときにトランザクションで作る）
- items の 1 件 = `{ title, place, memo, date, start, duration, order, createdAt }`
  - `date`: "YYYY-MM-DD"、null なら「💡 行きたい候補（日時未定）」
  - `start`: "HH:MM"。null なら時刻なし（日にある予定なら「時間未定」＝順番だけ持つ。候補は常に null）
  - `duration`: 分（デフォルト 60 分 ＝ 予定を入れると 1 時間枠を取る）
  - `order`: 日（または候補）の中の並び順。古いデータに無い場合は開始時刻順とみなし、次に並びを変えたとき振り直す
- 時間未定の予定：追加・編集シートの「時間を決めない（順番だけ）」で作る。直前の時刻のある予定の終わりを「16:00以降」と目安表示。
  時間を使わないので、詰め直しでは飛ばす。時間未定の予定を動かしたときは順番だけ変え、ほかの予定の時刻は動かさない
- 末尾に足す操作（候補を日程に入れる・別の日へ移動・候補に戻す）では、移動先の時刻は詰め直さない（決まっている時刻を動かさない）
- 予定を追加すると、開始時刻はその日の最後の予定の終わり（その日の最初なら 9:00）
- 「上へ / 下へ」で入れ替えると、その日の最初の開始時刻を基準に、各予定の長さを保って時刻を詰め直す
- ドラッグ＆ドロップ：各予定の ⠿（つまみ）を押して動かす。同じ日の入れ替え・別の日への移動・候補との行き来ができ、
  移動先の日（と、抜けた元の日）を上と同じルールで詰め直す。つまみだけ `touch-action: none` にして、ほかの場所はスクロールできる。
  ドラッグ中は他の人の編集による描き直しを待たせ、ドロップ後に描き直す
  iPhone の Safari は touch-action だけではスクロールを止めきれないので、つまみの touchstart とドラッグ中の touchmove を
  preventDefault している。それでも中断（pointercancel）されたら、元に戻さずその位置に置く
- 候補は「日程に入れる」で日を選ぶと、その日の最後に入る。日程から候補に戻すこともできる
- 場所はタップで Google マップを開く
- リンク：`links: [{ type, url }]` をいくつでも。種類（未設定 / 公式サイト / 予約サイト / 紹介動画 / 地図 / メニュー / その他）は
  見た目のラベルだけ。種類が未設定なら YouTube などは「紹介動画」、Google マップは「地図」と推測する。
  http / https 以外（javascript: など）は保存しない・表示しない。新しいタブで noopener noreferrer で開く
- 画面は 2 段階
  - 全体（イベント画面）：日ごとのカード（件数・時間帯・今日の印）。予定は全部 ⠿ 付きの小さな行で並べ、別の日のカードへドラッグして移せる。日付の行をタップでその日へ
  - 1 日（`#/g/{id}/e/{eventId}/d/{YYYY-MM-DD}`）：‹ › で前後の日へ。予定は長さに比例した高さ（1 時間 ≒ 64px）で表示し、
    ドラッグ・追加・候補からの取り込みはここで行う。別の日へは ⋮ →「別の日へ移動」
  - 1 日だけのイベントは、全体を挟まずに 1 日の形で表示
- イベント画面は「🗓 旅程」「📝 リスト」のタブで切り替える（最後に開いたタブをイベントごとに端末へ保存）
- 「💡 行きたい候補」は旅程の一番上。見出しのタップで折りたためる（端末へ保存）
- 端末だけの表示設定は `prefs`（localStorage、`ouchi-share:` 接頭辞）。保存できない環境でも表示は動く
- イベントの期間を変えて範囲外になった予定は「⚠️ イベント期間外の予定」にまとめて表示（消さない）

## カレンダーと普段の予定

- グループ画面は「📅 カレンダー」「✈️ イベント」「📝 リスト」（日常のリスト）のタブ（最後に開いたタブを端末に保存。初期はカレンダー）
- 月のカレンダー：イベントは期間の帯（週をまたぐと分割、1 週に 3 段まで、超えた分は「+」）、旅程の予定と普段の予定はマスの中に名前（1 日 3 件まで、超えたら「+n」。普段の予定はオレンジ・旅程の予定は青の線。小さい文字で、省略せずに折り返して全部出す。前の週から続く帯は絵文字を省く）
- 日をタップすると下にその日の一覧（イベント → その日の画面へ、旅程の予定 → その日の画面へ、普段の予定 → 編集・削除）
- 普段の予定：`groups/{id}/plans/{planId}` = `{ title, date（null なら日付未定）, endDate（何日か続くときの終わりの日。null なら 1 日）, start（null なら終日）, duration, place, memo, links, participants }`
  - リンクは旅程の予定と同じ入力欄（種類 ＋ URL をいくつでも、最大 20 件）。一覧ではメモの下にボタンで並ぶ
  - カレンダー右下の ＋ を長押し →「＋ 予定を1つ追加」で、日付を選ばなくても追加できる（日付の初期値は選んでいる日）
  - 月ごとに季節の色と絵文字（1 月 🎍 赤、4 月 🌸 桜色、8 月 🌻 橙、10 月 🎃 オレンジ、12 月 🎄 緑 など。SEASONS）を、見出し・曜日の帯・枠に付ける
  - カレンダーを左右にスワイプすると前後の月へ。今の月の表の左右に、となりの月の表（予定の点・帯も本物）を並べておき、
    指に付いて一緒に動く。離すとその月の位置までするっと動いてから描き直す（少しだけなら戻る）。‹ › ボタンも同じ動き
  - 選んでいる日をもう一度タップ（ダブルタップでも）すると、その日の予定の追加画面へ
  - 日付を長押しすると複数選択（そのまま指を動かすと、長押しした日から指のある日までを続けて選ぶ。戻せば縮む。長押しした日が選択済みなら外す）。選択中はタップで選ぶ・外す。
    下のバーの「予定を追加」で、選んだ日すべてに同じ予定を 1 件ずつ入れる（通知は 1 通にまとめる）。
    選んだ日が連続していれば「1 つの予定にする」（開始日〜終わりの日）が初期値
  - 「何日か続く（終わりの日を入れる）」で endDate を持つ予定にできる。終日扱いで、カレンダーには緑の帯（イベントはオレンジ）。
    その日の一覧では「〇日目」と期間を表示。リマインドは開始日の前日（「（〜M/D）」付き）
  - 「日付を決めない」で登録した予定は、カレンダーの下の「📌 日付未定の予定」に並ぶ。編集で日付を入れるとカレンダーへ移る
- 参加者：イベントと普段の予定の `participants`（uid の配列。空なら全員）。カレンダー上部で人を選ぶと、
  その人が参加する（または全員の）ものだけ表示。選択は端末に保存。人を選んだまま予定を追加すると、その人が参加者に入る

## アプリ全体の ＋ ボタン・最後に開いたグループ

- ＋ ボタンはアプリ全体で 1 つ（globalFab。どの画面でも右下）。タップ：📋 URLから登録、長押し：＋ 予定を1つ追加 ／ 📝 テキストでまとめて書く
  - 登録先は、グループの中ならそのグループ。外（ホームなど）では、参加中のグループが 1 つならそれ、2 つ以上なら押したときに「どのグループに？」を選ぶ（前回のグループがいちばん上）。グループがなければ出さない
  - 「予定を1つ追加」はそのグループのカレンダーを開いてから追加の画面を出す（pendingCalendarAdd）
  - 下に入力欄がある画面（.add-bar）ではその上に出す。テキスト予定表・日付の複数選択中は隠す。シートはその上にかぶさる
  - URLから登録は、クリップボードを先に読んでから（タップの瞬間でないと読めない）グループのリストを読み込む
- アプリを開いた最初の 1 回だけ、ホームなら最後に開いていたグループの画面から始める（‹ でホームに戻れる。戻ったあとはホームのまま）。
  グループが見つからなければ lastGroup を消してホームへ

## テキスト予定表（`#/g/{id}/text`。グループの普段の予定を文章で書く）

- 1 行 1 件：「10/9 10:00 歯医者 @〇〇歯科」「10/9 14:00-15:30 面談」「10/12 運動会」「10/20-10/22 帰省」「未定 車検の予約」
  - 時刻なしは終日、「@」のあとは場所、「-」の範囲は何日も続く予定。年は省略可（今日より前の月日は来年）。全角でも読める（NFKC）
- 開くと、これから先の予定と日付未定の予定がこの書き方で並ぶ（過ぎた予定は出さない。カレンダーには残る。
  今日より前に始まった予定など、年が要るものは年付きで書き出す）
- 書いている間「読み取り結果」に ✅ / ⚠️。保存のときは、開いたときの行と比べて追加・変更・削除を出し、確認してから反映
  - 同じ行はそのまま、なくなった行と同じ名前の新しい行は「変更」（参加者・メモ・リンクを残す）、残りは追加・削除
  - 追加があればグループに 1 通だけ通知。書いている途中にほかの人が変えても入力欄は書き換えない（保存後・開き直しで反映）
- 開き方：グループのメニュー「📝 テキスト予定表」、カレンダー右下の＋を長押し →「📝 テキストでまとめて書く」
  （＋の長押しで、＋の上にメニューが伸びて出る。＋は×に回る。タップは今までどおり予定を 1 つ追加。fabWithMenu）
  （長押ししたまま指をずらすと指の下の項目が光り、離したところを実行。項目の外で離したらメニューは開いたまま）
  ＋のタップ：📋 URLから登録（タップの瞬間ならクリップボードを読めるので）。長押しメニュー：＋ 予定を1つ追加 ／ 📝 テキストでまとめて書く
- 画面の下のメニュー（固定。キーボードが出ているときはそのすぐ上に付いていく。visualViewport）：
  入力の補助（今日・明日・📅 日付・🕐 時刻・〜 期間・@ 場所・未定・↵ 次の行。カーソルの位置に入れる。横にスクロール）と「元に戻す」「💾 保存」
- 「@」は前に空白がなくても場所の区切り。名前がない行（「10/9 @駅前」など）は ⚠️
- iPhone アプリ版では、これをそのまま表示するウィジェットを作る予定（ウィジェットには文字を入力できないので、タップでこの画面を開く）

## 欲しいもの系リスト（欲しいもの・行きたいところ・食べに行きたい・食べたいもの）

- リストの種類 `type: 'wish'`。`variant` で入力する項目と言葉が変わる（中身の仕組みは共通）
  - `buy`（なし も同じ）：🛍️ 欲しいもの。「🛒 買った / 🙅 あきらめた」
  - `place`：📍 行きたいところ・🍴 食べに行きたい（ひな形の名前と絵文字が違うだけ）。場所（タップで地図）、「✅ 行った / 🙅 やめた」＋★評価、
    ⋮ →「📅 予定にする」で場所とリンク付きのカレンダーの予定を作る
  - `food`：🍳 食べたいもの。「🍳 作る / 🛒 買う / 🍴 食べに行く」、「😋 食べた / 🙅 やめた」＋★評価
- 欲しい度（❤️。欲しいもの `buy` だけ）：タップで +1、長押しで連続（だんだん速く）。押している間は画面だけ増やし、離して 0.7 秒後にまとめて保存。
  items に `hearts`（足したときの数）と `heartsAt`（足した時刻）。今の数 = hearts を「足してからの週数」回半分（切り捨て）。
  まだ hearts がないものは ❤️5・作成時刻から（5 → 2 → 1 → 0 で 3 週間ほど残る）。0 になったら「💭 昔欲しかったもの」（折りたたみ。ハートを押すと戻る）。ハートの多い順に並べる
- 「＋ リストを追加」に 4 つのひな形。⋮ →「ほかのリストへ移す」で欲しいもの系のリストどうしで移せる
- items の 1 件 = `{ text（名前・メモ）, url, photoId, place, how, status, result（結果・感想）, rating（0〜5）, closedAt, createdAt, createdBy }`
- リンクのタイトルと画像：URL を貼ると Workers の `/preview` が取ってきて、名前（空のとき）と写真（ないとき）に入れる
  - TikTok・YouTube は公式の oEmbed、ほかはページの og:title / og:image。画像は期限切れになるので、縮小して写真として保存する
  - TikTok の説明文は長いので、ハッシュタグを除いて最初のひと区切りだけを名前にする
  - 取れないサイトもある（食べログは Workers からだと取れない、Instagram・X はログインが必要など）。その場合は手で入れる
- 「📋 URLから登録」（カレンダー右下の＋をタップ）：ボタンを押すとクリップボードを読み（iPhone は「ペースト」の確認が出る）、
  登録先（欲しいもの系のリスト。前回選んだものが最初から選ばれる）を選んで追加する。リンク以外にコピーされた文字は使わない
  - iPhone は「指でボタンを押した瞬間」しかクリップボードを読ませない（＋を長押しして指をずらして選んだときなどは断られる）。
    読めなかったら「📋 貼り付け」を押すよう案内する。登録画面の URL の欄の横の「📋 貼り付け」はふつうのタップなので確実に読める
  - ブラウザ版は、開いただけで自動でクリップボードを読むことはできない。iPhone アプリ版で、開いたときの自動確認と共有メニューからの登録を足す予定
- 画面下の入力欄にそのまま書くとメモで追加。URL が含まれていればリンクとして取り出す（TikTok・YouTube・Amazon・楽天などはラベル表示）
- 📷 で写真付きで追加（スマホなら撮影も可）。⋯ →「詳しく追加」で URL・写真を入れたシート
- 「完了」→「🛒 買った / 🙅 あきらめた」＋結果のメモでクローズ。完了済みは折りたたみ、「未完了に戻す」もできる
- 写真：Firebase Storage は無料プランで使えないため、`groups/{id}/photos/{photoId}` に縮小 JPEG（長い辺 1024px→800→640 と段階的に、850KB 以下）を
  data URL の文字列で 1 枚 1 ドキュメント保存（ルールで 900KB 以下・作成者は本人）。アイテムやリストを消すと写真も消す

## 貸し借りリスト

- items の 1 件 = `{ from（貸した人）, to（借りた人）, kind: 'money' | 'item', amount（円）, item（もの）, memo, date, settled, createdAt, createdBy }`

## 通常のリスト（チェックリスト）のリンク
- アイテムは「名前＋リンクいくつでも」。links（[{ type, url }]、予定のリンクと同じ形）で持つ。v88 の url 1 つも読む
- 入力欄に「電池 https://… https://…」と貼ると、URL 以外の文字が名前、URL はすべてリンク。URL だけなら、あとで最初のリンクのタイトルを名前に入れる
- 名前の下にサイト名のボタン（▶️ YouTube、📦 Amazon など）。押すとリンクを開く。右の ✏️ で名前とリンクを編集（リンクの欄に URL をいくつも貼ると、行が分かれる。予定のリンクの欄も同じ）
- グループ画面のカードの中では「🔗 名前」
- ＋の短押し（📋 リンクを登録）の登録先に、欲しいもの系のリストに続けて通常のリストも出す。通常のリストを選ぶと写真・場所の欄は出さず、名前とリンクだけ登録する。コピーした内容に URL がいくつもあれば、通常のリストには全部をリンクにする（欲しいもの系は最初の 1 つ）
- ＋の短押しは、押したらすぐ登録の画面を出し、クリップボードの URL と登録先のリストは読み終わってから入れる（読み終わるのを待ってから画面を出すと、iPhone で何も起きないように見えることがあったため）

## 日記
- グループ画面のタブ「📔 日記」（カレンダー・イベント・リストの横）。タブが 4 つなので、タブは絵文字を上・名前を下に並べる
- 1 件ごとに、タイトル・日時・メンバー・タグ・内容をどれも好きなだけ入れられる（全部空は保存しない）。書くとき日時は「いま」（0.01 秒まで）が入っている

- タグ（groups/{id}/diaryTags）は誰でも自由に作れる：書く画面の「＋ タグを作る」（書きかけを消さないよう画面の中で名前を聞く）、タブの「🏷 タグの管理」で作る・名前を変える・消す（消しても日記は残り、タグが外れる）
- 保存先 groups/{id}/diary（title, at, members, tags, body, createdAt, createdBy, updatedAt）。メンバーなら誰でも読む・書く・直す・消すことができる

## 通知

- Firebase は無料プラン（Spark）のまま。Cloud Functions（有料プランが必要）は使わず、**Cloudflare Workers（無料）**で送る（`worker/`）
- 受け取る：Firebase Cloud Messaging（FCM）の Web Push。端末ごとのトークンと受け取る種類を `push/{uid}` に保存（本人だけ読み書き）
  - `{ tokens: { [id]: { token, ua, updatedAt } }, prefs: { news, plans, reminders } }`
  - iPhone はホーム画面に追加したアプリ（iOS 16.4 以降）でだけ受け取れる。表示は `sw.js` の push イベントで行う（FCM はデータだけで送る）
- 送る：アプリがお知らせ・予定・イベントを追加したら、Workers に ID トークン付きで頼む（`js/push.js` の `notify`）
  - Workers が ID トークンの署名を確かめ、頼んだ人がグループのメンバーか（アプリのお知らせは管理者か）を確認してから、
    メンバー（参加者が決まっていればその人）から本人を除いた人の全端末へ送る。受け取らない設定の人には送らない
  - 送りすぎの上限：1 人 1 分に 10 回まで。無効になったトークンは自動で消す
  - 毎日 20 時（日本時間）に、翌日の普段の予定・イベントのリマインド（人ごとに 1 通にまとめる）
- 設定画面：ホームの ⋯ →「🔔 通知の設定」（この端末でオン・オフ、受け取る種類）
- 準備（Cloudflare のアカウント・サービスアカウントキー・VAPID キー）は `worker/README.md`。`js/firebase.js` の `VAPID_KEY` と `NOTIFY_URL` が空のあいだは「準備中」

  - 📢 管理者お知らせを書く
  - 👥 メンバーの管理 ＞ メンバーを見る（外す・復旧ID）・👑 管理者を設定（オーナー）・招待リンクの作り直し（オーナー）

## お知らせ

- アプリからのお知らせ `announcements/{id}`（アプリの管理者だけ書ける・全員が読める。書く・再通知・削除は管理者ダッシュボードから）と、
  グループのお知らせ `groups/{id}/announcements/{id}`（メンバーなら誰でも書ける。消せるのは書いた本人とオーナー）
- 1 件 = `{ title, body, createdAt, createdBy, createdByName }`
- 既読は `reads/{uid}` の `seen` マップ（key は `app:ID` / `g:GID:ID`、本人だけ読み書き）。自分が書いたものは既読あつかい
- アプリを開いたとき（アプリのお知らせ）と、グループを開いたとき（そのグループのお知らせ）に、未読を古い順に 1 件ずつポップアップ
  - 「既読にする」→ reads に記録。「あとで見る」（背景タップも同じ）→ この起動中は出さず、次に開いたときにまた出す
  - 既読情報を読み込むまでは出さない（既読のものが一瞬出ないように）。ログイン処理中・名前の入力前も出さない
- 一覧：ホームの ⋯ →「アプリからのお知らせ」（`#/news`）、グループの ⋯ →「お知らせ」（`#/g/{id}/news`）。未読に印、メニューに未読数
- 再アナウンス（一覧の 🔁。消せる人と同じ人だけ）：`announcedAt / announcedBy / announcedByName` を書き、通知もあらためて送る。
  `announcedAt` より前に読んだ人は未読に戻り、またポップアップが出る（再アナウンスした本人は既読あつかい）。一覧ではいちばん上に移る。
  ルールで、更新できるのはこの 3 つの項目だけ

## ログインボーナス（チケット＋おまけのスタンプ。グループごと）

- その日はじめてグループを開いたら「🎁 〇〇のログインボーナス」（お知らせのポップアップを出している途中なら、終わってから）
  - 主役はチケット（🥉ブロンズ・🥈シルバー・🥇ゴールド）。その月の何回目のログインかで、配布表どおりの枚数をもらう（毎月 1 日に 1 回目から）
  - おまけで季節のスタンプを 1 つ（月ごとに 5 種類。5% でレア 🌈🦄👑💎🍀🐉）。記念スタンプ：はじめての日 🎉、7 日連続 🏅、30 日連続 🏆、合計 50 日 🎖️、合計 100 日 💯
- 配布表 `config/bonus` = `{ days: { "N": { bronze, silver, gold } }, updatedAt }`：アプリの管理者が管理者ダッシュボードで編集（全グループ共通）。
  ない間は初期値（毎回 🥉1、7・14・21 回目 🥈1、28 回目 🥇1）
- `groups/{id}/bonus/{uid}` = `{ lastDate, streak, total, stamps, lastStamp, month, monthDays, tickets: { bronze, silver, gold }, updatedAt }`。
  トランザクションで、同じ日に二重にもらわない。メンバーはみんなの記録を読める。書けるのは本人だけ
- ごほうび `groups/{id}/rewards/{rid}` = `{ title, emoji, ticket, count }`：オーナーが登録（例：🎮 ゲーム30分 ＝ 🥉3枚）。
  メンバーは「🎟 チケット・ごほうび」（`#/g/{id}/tickets`、グループの ⋯ から）で交換 → チケットを減らし、
  交換の記録 `groups/{id}/redemptions/{xid}` = `{ uid, name, title, emoji, ticket, count, at, done }` を残して、グループに通知（kind: 'reward'）。
  オーナーが記録をタップして「済み」にする
- 両替・換金のレート `groups/{id}/settings/tickets` = `{ upgrade: { silver: ブロンズ何枚で 1 枚, gold: シルバー何枚で 1 枚 }, yen: { bronze, silver, gold }, updatedAt }`。
  オーナー・管理者が「⚙️ レート」で決める（0 は使えない）。両替は上にも下にも同じレートで 1 回ずつ（トランザクション）。
  換金はチケットを減らして記録（kind: 'cash', yen）を残し、通知。お金を渡したらオーナー・管理者が「済み」にする
- 「🎟 チケット・ごほうび」の画面：持っているチケット、今月の受け取り表（何回目に何がもらえるか・受け取り済み・次）、ごほうび、交換の記録
- スタンプ帳（`#/g/{id}/stamps`）、メンバー一覧の 🔥 連続日数とスタンプの種類数

## プロフィール

- 項目：アイコン（絵文字か写真）・名前・**肩書き**（グループでの立ち位置。例：パパ、長女、幹事。権限の「役割」とは別）・3 つの色
  - メインカラー：アプリの見た目の色（--accent）。サブカラー：背景などの薄い色（--accent-soft）。どちらも自分の画面だけ
  - サードカラー（識別カラー）：みんなの画面での「その人の色」。アイコンの丸・参加者のチップ・カレンダーの人の絞り込み・
    参加者が 1 人の予定の線に使う。決めていなければ uid から決まった色（personColor）
- 全体の設定 `profiles/{uid}` = `{ icon, photo, title, colors: { main, sub, third }, updatedAt }`（名前はログインの表示名）。本人だけ読み書き
  - photo：アイコンの写真。選んだ写真を「写真を切り抜く」画面（四角い枠の中の丸い点線がアイコンの範囲。ドラッグで位置、2 本指・スライダー・ホイールで大きさ）で
    切り抜いた 160px の JPEG の data URL（数 KB〜十数 KB。ルールで 60,000 文字まで）。あれば絵文字より優先。
    グループの members.{uid}.photo にも書き写す（「全体の設定を使う」はアイコンと一緒）
- 色の選び方：プリセット 10 色、**色のセット**（メイン・サブ・サードが同系色の 12 組。COLOR_SETS）、
  **カラーパレット**（🎨。12 色相 × 5 段階の濃さ）、自由に選ぶ（type=color）
  - アカウントのメニュー・ホームのあいさつ →「👤 プロフィール」
- グループごと：`members.{uid}` の `name / icon / title / colors` と `custom`（true の項目は「このグループだけ変える」）
  - グループのメニュー・メンバー一覧 →「👤 このグループでのプロフィール」。項目ごとに「全体の設定を使う」を選べる
  - 全体の設定を保存すると、custom でない項目を参加中の全グループに書き写す（ほかの人はグループのデータだけで見られる）。
    グループに参加・作成したときも書き写す
- 画面の色：グループの中ではそのグループでの自分の色、外では全体の設定の色（route ごとに applyTheme）

## ログイン方法の連携

- アカウントのメニュー →「🔗 ログイン方法の連携」（ゲストは「アカウントを連携（ゲストから引き継ぐ）」）
- 1 つの Firebase のアカウントに Google・Apple をまとめる（linkWithPopup / iPhone アプリでは linkWithCredential）。どれでログインしても同じデータ
- ゲストが連携すると、そのデータ（参加中のグループ・名前）のまま正式なアカウントになる（ゲストからの昇格）。グループのゲスト表示を外し、復旧ID を消す
- Apple との連携は iPhone アプリの中だけ（Web で Apple を使うには Apple 側のサービス設定が別に要る）。
  Apple でサインインした人も、アプリで Google を連携すれば、ブラウザ版でも Google で同じデータにログインできる
- 連携が 2 つ以上あるときは「外す」ができる（最後の 1 つは外せない）。すでに別のデータで使われているアカウントは連携できない

## ゲストの復旧（スマホ紛失時）

匿名アカウントは別の端末から同じアカウントに戻れない（それには Cloud Functions ＝有料プランが必要）ため、
**新しいゲストが元のゲストのグループでの席を引き継ぐ**方式にしている。リストはグループ共有なので実質的に元どおりになる。

1. ゲストがグループに参加する（またはグループを開く）と、12 文字の復旧ID が `recovery/{code}` に作られる
2. オーナーはメンバー一覧でゲストの「復旧ID」を開き、ID と QR（`#/recover/{code}`）を確認できる。ゲスト本人も右上メニューから見られる
3. 新しい端末で「復旧IDで戻る」から入力 or QR を読むと
   - 新しいゲストを作り、元のゲストのメンバー情報を消して自分を同じ役割・名前で追加（ルール `isValidRecovery`）
   - 続けて元の uid を `memberIds` から外す（ルール `isStaleRemoval`）→ なくした端末からは読めなくなる
   - 使った復旧ID を消し、新しい復旧ID を作る
- 引き継げるのはゲストの席だけ（Google ログインの人は普通にログインし直せばよい）
- Google アカウントに引き継いだゲストの復旧ID は消す

## ホームのグループのカード

- タップでグループの画面へ
- iPhone のメールと同じく、**左にフリック**するとカードが左に寄り、右側に「📋 招待」「⚙️ 設定」のボタンが出て止まる。ボタンをタップして初めて実行する
  - 半分より多く引っぱって離すと開いたまま、少しなら戻る。右へのフリックはしない（開いているときに右へ戻すと閉じる）
  - 開けるのは 1 枚だけ。開いているカードをタップ・カードの外を触る・ほかのカードを触ると閉じる（そのタップでは画面を移らない）
- **長押し**でも設定を開ける
- 設定（groupMenu。グループの画面の ⋯ と同じ中身）は、下から出るシートではなく、画面の真ん中に浮かぶウィンドウ（openSheet の asWindow）で出す
- シート・ウィンドウはすべて、下にスワイプして閉じられる（上の「つまみ」が目印。90px 以上で閉じ、少しなら戻る。中身がいちばん上のときだけ・入力欄の上からは動かない・data-noswipe の部品（写真の切り抜き）の上からも動かない）

## ホーム画面に追加の案内
- ブラウザで開いているとき（ホーム画面から開いていない・iPhone アプリでもない）だけ、ホームのいちばん上に「📲 ホーム画面に追加しよう」を出す。× で消せる（prefs の installHintHidden）。右上「⋯」のメニューからはいつでも見られる
- やり方は端末に合わせて iPhone（Safari の「…」→ 共有 → ホーム画面に追加 → Webアプリとして開く → 追加。画像は img/install-ios-*.jpg）か Android（⋮ → ホーム画面に追加）。PC では両方
- Android の Chrome などで beforeinstallprompt が来ていれば「このまま追加する」ボタンも出す
- iPhone はホーム画面のアプリと Safari でログインが別なので、ログインし直し（ゲストは復旧ID）と通知はホーム画面から、を書いておく

## グループの管理者

- `members.{uid}.role`：'owner'（オーナー）/ 'admin'（管理者）/ 'member'。オーナーがグループの ⋯ →「👑 管理者を設定」か、メンバー一覧のメニューで切り替える
  - ルールでは変えた人の uid を取り出せないので、`roleTarget` に対象の uid を一緒に書く。オーナー以外・オーナー自身・オーナーの役割は変えられない
- 管理者ができること：ごほうびの登録・編集・削除、交換・換金の「済み」、お知らせの削除・再アナウンス、チケットのレート、スタンプの記録の削除
- オーナーだけ：管理者を決める、メンバーを外す、招待リンクの作り直し、グループの削除、復旧ID の発行

## 権限

| 操作 | 誰ができるか |
|---|---|
| グループ作成 | `admins/{uid}` に登録された Google ログインユーザー |
| グループ・リストの閲覧／編集 | グループのメンバー（ゲストも可） |
| 招待リンクの作り直し、グループ削除 | グループのオーナー |
| メンバーを外す | オーナー（自分以外）。オーナー以外は自分だけ退出できる（ルール `isMemberRemoval`）。外すとその人の復旧ID も消す |
| グループへの参加 | 正しい招待コードを持っている人（ゲスト / Google） |

- ゲスト = Firebase の匿名ログイン。「Google アカウントに引き継ぐ」で同じユーザーのまま Google ログインに移行できる
- 許可リストにメールアドレスを使わないのは、公開リポジトリにメールアドレスを載せないため

## 初期設定（管理者の登録）

1. `firebase deploy --only firestore:rules` でルールを公開（Firebase CLI。コンソールに貼り付けてもよい）
2. アプリを開き Google でログイン → ホーム画面に表示される「ユーザーID」をコピー
3. Firebase コンソール → Firestore Database → データ →「コレクションを開始」
   - コレクション ID: `admins`
   - ドキュメント ID: 手順 2 のユーザーID
   - フィールド: `note`（string）に自分の名前など、何でもよい
4. アプリに戻ると「＋ グループを作成」が表示される

## 決定事項

| 項目 | 決定 |
|---|---|
| 共有単位 | グループ |
| 別グループへの展開 | コピー方式（同期はしない）。実装は後回し |
| 最初の機能 | チェックリスト |
| 参加方法 | 招待リンク。ゲスト（ニックネームのみ）か Google ログインで参加 |
| ゲストの権限 | 編集も可（案B）。必要になったらグループごとに切り替え（案C）へ拡張 |
| グループ作成 | 許可リストの人だけ（知らない人に無料枠を使われないように） |

## 既知の注意点

- iPhone のホーム画面から起動した PWA では、Google ログインのポップアップがうまく動かない場合がある。その場合は Safari で開いてログインする
- ゲストのままログアウトしたり Safari のデータを消したりすると、同じゲストには戻れない（招待リンクから新しいゲストとして再参加は可能）
