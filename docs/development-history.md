# 開発履歴 — Claude Code でつくった「おうちでシェア」

家族・友だち向けの共有アプリ「おうちでシェア（ouchi-share）」を、**開発者 1 人と Claude Code** でつくった記録。
このファイルの数字・出来事は、Git の履歴・CHANGELOG.md・Claude Code の会話の記録から集めた（2026-10-08 時点）。

## ひとことで

- **11 日間**（2026-09-28〜10-08。作業した日は 8 日）で、空のリポジトリから、ログイン・同期・通知・iPhone アプリの土台まであるアプリになった
- 開発者がしたのは、**日本語で「こうしたい」を伝える・決める・実機で触る・アカウントやお金の操作**。設計・実装・テスト・公開・資料づくりは Claude Code
- 会話はスマホとパソコンから。依頼はおよそ **250 回**、送ったスクリーンショットは **28 枚**、Claude Code の操作（ファイルの編集、コマンドの実行、ブラウザの操作など）はおよそ **1,800 回**

## 1 回の開発の流れ（いつものサイクル）

1. **開発者が日本語で頼む**（スマホからのことも多い）。例：「通常リストに対して複数リンクを貼れるようにして。テキスト＋任意の複数リンクで」「プラス短押しで URL から登録、長押しで項目追加」
2. **Claude Code がコードを読んで方針を決める**。仕様が決めきれないところだけ選択肢を出して聞く（例：TestFlight にするか、ログボの配り方をどうするか）
3. **実装**：画面（JavaScript・CSS）、データ（Firestore）、セキュリティルール、必要なら Cloudflare Workers まで、まとめて変える
4. **自分で確かめる**：テスト用のページを組み立てて組み込みのブラウザで動かす。ログインが要るところは、開発者の Chrome で実際のデータを使って確かめ、作ったテストデータは最後に消す
5. **公開**：版を上げて（`scripts/bump-version.mjs`）、コミット・プッシュ、ルールや Workers の公開まで
6. **報告とスマホへの通知**：何を変えたか・何を確かめたか・何が未確認かを日本語で報告し、スマホに「v89 をプッシュしました」と通知
7. **開発者が実機で触って、次の依頼**。うまくいかなければスクリーンショットを送る

## Claude Code だからできたこと

このプロジェクトで実際に使った Claude Code の機能と、それで何ができたか。

### 1. 頼んだら「公開まで」終わる（エージェントとして動く）
- リポジトリのファイルを自分で探して読み、直接書き換え、コマンドを実行する。コード片を貼り付けてもらう必要がない
- `git push`（GitHub Pages に公開）、`firebase deploy`（データのルールの公開）、`wrangler deploy`（Cloudflare Workers の公開）まで Claude Code が実行する。開発者は「お願い」と言うだけで、数分後には自分のスマホで新しい版を触れる
- 1 回の依頼で、画面・データ・ルール・サーバー側（Workers）・資料をまとめて変える。例：日記は「保存先とルール → 画面 → 見た目 → 設計メモ」を一度に

### 2. 自分で画面を動かして確かめる（ブラウザの操作）
- Claude Code のデスクトップアプリの**組み込みのブラウザ**で、開発中の画面を開き、クリック・入力・スクリーンショット・コンソールの確認をする
- **Claude in Chrome** で開発者の Chrome（ログイン済み）を操作し、本物のデータで登録 → 表示 → 編集 → 削除まで通して確かめる。確かめたあとはテストデータを消す
- スマホの幅に切り替えて、はみ出しも確かめる（例：日記を足してタブが 4 つになったとき、幅 360px で文字がはみ出すのを見つけ、絵文字と名前を上下に並べる形に直した）
- ブラウザの操作は 11 日間でおよそ 600 回

### 3. スマホから頼めて、終わったらスマホに届く
- **Remote Control**：パソコンで動いている Claude Code のセッションに、スマホの Claude アプリから話しかけられる。外出先から「＋ボタンを全部のページに置いて」と頼める
- **完了の通知**：作業が終わるとスマホに通知が届く（「次からタスクが終わったらスマホに通知よろしく」と頼んでから、毎回）
- スマホで撮ったスクリーンショットをそのまま送ると、画面のどこがおかしいかを読み取って直す（「グループを選ぶ前の画面にも＋が出ているけど、どのグループに入るの？」→ グループが複数なら選んでもらう形に）

### 4. 覚えておく（記憶と指示書）
- 「毎回の公開で版を上げて、報告に版を書いて」「終わったら通知して」のような**好みや決まりを記憶**し、次の会話でも守る
- プロジェクトの決まりを **CLAUDE.md**（Claude Code が毎回読む指示書）に書いておく。例：「ブラウザ版・ホーム画面版・アプリ版の 3 つに対応し、動きが違うときはそれぞれに合わせる」「Chrome で確かめても実機は未確認として、実機確認リストに足す」
- 1 つのセッションを 11 日間続けた。会話が長くなると Claude Code が自動で要約して続けるので、前に決めたこと（ポップアップの閉じ方の決まりなど）を前提に話せる

### 5. やってよいこと・いけないことの線引き
- 秘密の値（Firebase のサービスアカウントキー）は Claude Code に渡さず、開発者が自分で Cloudflare に登録した。Claude Code は手順だけ案内する
- ログイン・支払い（Apple Developer の更新など）・Xcode のチームの選択は開発者が行う
- 公開（プッシュ・ルール・Workers）は「毎回聞かなくてよい」と最初に任せたので、そこは確認なしで進む。それ以外の取り消しにくい操作は、先に確認する

### 6. 会話で仕様を詰め、資料も残す
- 「カレンダーを左右スワイプしたとき、実態があってほしい」「びよーんはしてほしい」のような感覚的な言い方から、実装の形を提案して決める
- 決めたことは設計メモ（[design.md](design.md)）、作業の残りは [todo.md](todo.md)、構成は [architecture.md](architecture.md)、実機確認は [device-test.md](device-test.md) に、Claude Code が書いて更新し続ける

## 人がしたこと・AI だけでは難しかったこと

- **実機での確認**：iPhone の Safari・ホーム画面に追加したアプリでの動き（クリップボードの読み取り、並べ替えのあとのタップなど）は、パソコンの Chrome では再現できなかった。開発者が実機で触って報告し、Claude Code が原因の候補を挙げて直す、を繰り返している（[device-test.md](device-test.md)）
- **Mac・Xcode・Apple のアカウント**：古い Mac で使える Xcode の版の調査や手順は Claude Code、インストールやサインイン・署名は開発者
- **決めること**：何をつくるか、収益化しない、費用は年 99 ドルまで、といった方針は開発者が決めた
